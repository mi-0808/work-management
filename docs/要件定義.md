# 勤怠管理アプリ 要件定義

作成日: 2026-08-25 / ステータス: ドラフト（初回ヒアリングまとめ）

## 1. 背景・目的

- 現在、出退勤はスプレッドシート、スケジュールは Google カレンダーで運用している。これを 1 つのアプリに統合する。
- 社内は Google Workspace（Meet でミーティング）を利用しており、会社アカウントでの認証が前提。
- 将来的に社外のアルバイト等、Workspace アカウントを持たない人も参加させたい。アカウント発行の負担を避けるため、アプリ側で名簿管理し、個人の Google アカウントを連携する方式を取る。

## 2. 主要機能（3本柱）

### 2.1 出勤・退勤（打刻）

- 出勤 / 退勤の打刻（現行スプレッドシートの置き換え）
- 打刻時に「その日の予定（作業予定）」を登録できる
- 日別・月別の勤怠一覧の閲覧
- （要確認）休憩打刻、打刻修正の申請・承認フロー、CSV/スプレッドシート出力の要否

#### 打刻漏れの自動補完

- 名簿に各メンバーの「所定勤務時間帯」（例: 9:00–18:00）を登録する
- 補完の優先順位: **実打刻 > その日のシフト予定（カレンダー）の開始・終了時刻 > 名簿の所定時間帯**
- 退勤のみ打刻 → 出勤時刻を補完。出勤のみで退勤なし → 日付切替時に退勤時刻を補完
- 自動補完されたレコードは「自動補完」バッジで可視化し、本人が修正申請できる（無断確定はしない）

### 2.2 日報

- その日の業務内容を報告する日報の作成・提出
- 打刻時に登録した「予定」と対で見られること（予定 vs 実績）
- 管理者（上長）が日報を閲覧できる
- （要確認）コメント・既読などのフィードバック機能の要否

### 2.3 スケジュール

- シフト予定、行事（イベント）の登録・閲覧
- **Google カレンダー連携必須**: アプリで登録した予定を Google カレンダーに同期する
- Meet でのミーティングに対応（カレンダー予定に Meet リンクを付与できること）
- （要確認）同期方向は アプリ→カレンダー の一方向でよいか、双方向か

## 3. ユーザー・認証

### 3.1 ユーザー種別

| 種別 | 説明 |
|------|------|
| 社内メンバー | 会社の Google Workspace アカウントで認証 |
| 社外メンバー（バイト等） | Workspace アカウントは発行しない。アプリの名簿に登録し、本人の個人 Google アカウントを連携 |
| 管理者 | 名簿管理、勤怠・日報の閲覧、シフト・行事の管理 |

### 3.2 認証・連携

- Google OAuth によるログイン（Workspace アカウント / 個人アカウント両対応）
- 社内メンバーは Workspace ドメインで自動判別
- 社外メンバーは管理者が名簿に登録 → 招待 → 本人の Google アカウントを紐付け
- 連携した Google アカウントで、カレンダー予定の共有・Meet への参加ができること

### 3.3 会社（テナント）の作成と初期管理者

- Google ログイン後、所属する会社がなければ「会社を作成」できる
- **会社を作成した本人が自動的に管理者（オーナー）になる**
- 以降のメンバーは招待で参加し、デフォルト権限は「一般」。管理者が名簿から昇格できる（管理者は複数可）
- Workspace ドメインを会社に紐付けると、同一ドメインのアカウントはログインだけで自動参加できる（社外メンバーは招待制のまま）

### 3.4 名簿管理

- 管理者がメンバーの追加・編集・無効化を行える
- 社内 / 社外の区別、権限（一般 / 管理者）を持つ
- 所定勤務時間帯（打刻漏れ補完のベース値）を持つ
- Google アカウント連携状態を管理できる

## 4. 非機能・前提

- 段階導入: フェーズ1は自社メンバーのみ、フェーズ2で社外メンバー対応
- 現行データ（スプレッドシートの勤怠、Google カレンダーの予定）の移行要否は要確認
- モバイルからの打刻を想定（要確認: Web アプリで足りるか、ネイティブアプリが必要か）

## 5. スコープ外（現時点）

- 給与計算・給与連携
- 有給・休暇管理（要確認: 必要なら追加）
- Workspace 以外のカレンダー / 会議ツール対応
