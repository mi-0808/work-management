# デザイン規定

作成日: 2026-10-06 / 更新: 2026-10-06（全画面を作り直し、形を Apple 風に）

## 1. 目的

- Apple ヒューマンインターフェイスガイドライン（HIG）と Material Design 3（M3）に沿った画面にする
- **見た目（形・並べ方）は Apple**（iOS 26 のマップ・設定アプリが手本）。**色の決め方は M3**（MyHoodβ と同じ役割と値）。Google（Material）っぽい見た目（枠線の入力欄・枠線ボタン・影付きカード）にはしない
- 色・文字は姉妹アプリ MyHoodβ と同じにする。元は MyhoodBeta の `docs/ui/style-guide.md`（「カラートークン」「デザインシステムの標準値」）と `src/styles/theme.css`（origin/main、2026-10-04 時点）

## 2. どこに何があるか

| 場所 | 中身 |
|------|------|
| `frontend/src/tokens.css` | 値の実体（色・文字・余白・形・影・動き）。**値はここ以外に書かない** |
| `frontend/src/ui.css` | 共通部品の見た目 |
| `frontend/src/ui.tsx` | 共通部品（`Button` `Card` など） |
| `frontend/src/theme.ts` | 表示（自動/ライト/ダーク）の保存と切り替え。設定画面の「表示」から使う |
| `/catalog` | 部品と色を実物で並べた一覧。ライト・ダークを切り替えて見られる。部品を足したらここにも置く |
| `frontend/scripts/check-contrast.mjs` | `npm run check:contrast`。色の組み合わせのコントラストをライト・ダーク両方で検査する |

## 3. HIG と M3 の使い分け

| 項目 | 拠り所 | 決まり |
|------|--------|--------|
| 色の決め方 | M3 | 役割の名前（primary / surface …）で指定する |
| 形・並べ方 | HIG | グレーの地に明るい角丸のセル、大きく太い見出し、丸いアイコン、大きなタイルボタン（iOS 26 のマップ） |
| ナビゲーション | HIG | スマホは画面下に浮くタブバー（Liquid Glass）。PC（幅 1024px 以上）は左のサイドバー（`Sidebar`。macOS の App Store・システム設定と同じ）。戻るは左上のガラスの丸ボタン |
| 押せる大きさ | HIG・M3 | 48px 以上（HIG 44pt と M3 48dp の大きい方。MyHood は 44px） |
| 書体 | HIG | 端末のシステムフォント（iPhone は SF Pro とヒラギノ） |
| 文字サイズ・余白 | MyHood | MyHood と同じ寸法（1rem = 17px 基準）。角丸の大きさとセクションの間だけ iOS 26 に合わせて足した |
| 押した時の見せ方 | M3 | 新しい色を作らず、上に色を重ねる（state layer） |
| ライト/ダーク | 両方 | 両方に対応し、端末の設定に従う |

## 4. 色

### 5つのルール（MyHood と共通）

1. **色は役割の名前でしか指定しない**（hex を書かない）
2. **色みを持つのは primary（青）と error（赤）だけ。** ほかは無彩色
3. **文字は必ず「on-○○」を対応する面に乗せる**（primary の上は on-primary）
4. **強さは4段階だけ**: 塗り（primary）＞ 淡い塗り（primary-container）＞ 枠（outline）＞ 文字だけ。塗りは1画面に1つ
5. **押す・なぞる・フォーカスで新しい色を作らない。** 上に色を重ねる（なぞる 8% / 押す 10% / フォーカス 10%）。フォーカス枠は primary の 2px

成功・注意の専用色は作らない。中抜け中・打刻漏れなどはアイコンと文言で伝える。

### 地とセル（iOS のグループ化された画面）

役割の値の組み合わせで、新しい色ではない。ライトは「グレーの地に白いセル」、ダークは「黒い地に濃いグレーのセル」。

| 変数 | ライト | ダーク | 使い道 |
|------|--------|--------|--------|
| `--ios-grouped-bg` | surface-container `#f5f5f5` | surface `#121212` | 画面の地・ヘッダー |
| `--ios-cell` | surface `#ffffff` | surface-container `#1e1e1e` | カード・リストのセル・PC のサイドバー |
| `--ios-fill` | surface-container-high `#efefef` | surface-container-high `#282828` | 入力欄・セグメントの溝・グレーの丸アイコン |

### 役割（15色）

変数名は `--md-sys-color-<役割>`。MyHood と同じ名前・同じ値。

| 役割 | ライト | ダーク | 使い道 |
|------|--------|--------|--------|
| primary | `#0063e6` | `#99c5ff` | 塗りボタン・リンク・選択中・フォーカス枠 |
| on-primary | `#ffffff` | `#002657` | primary の上の文字 |
| primary-container | `#e0eeff` | `#004299` | 淡い塗り（選択中・勤務中の札） |
| on-primary-container | `#002c66` | `#d6e8ff` | その上の文字 |
| surface | `#ffffff` | `#121212` | 画面・カード |
| surface-container | `#f5f5f5` | `#1e1e1e` | 入れ子の面 |
| surface-container-high | `#efefef` | `#282828` | 押している間の面 |
| on-surface | `#171717` | `#e6e6e6` | 本文・見出し・入力値 |
| on-surface-variant | `#525252` | `#b0b0b0` | ラベル・補足・プレースホルダー |
| outline | `#8a8a8a` | `#8c8c8c` | 部品の境界（入力欄の枠） |
| outline-variant | `#e5e5e5` | `#3a3a3a` | 飾りの線（コントラストの対象外） |
| error | `#ba1a1a` | `#ffb4ab` | エラー・削除・件数の印 |
| on-error | `#ffffff` | `#690005` | error の上の文字 |
| error-container | `#ffdad6` | `#93000a` | エラーの面 |
| on-error-container | `#410002` | `#ffdad6` | その上の文字 |

### ルール2の例外（「中身の色」）

| 種類 | 場所 |
|------|------|
| メンバーの頭文字アイコン | MyHood の洋パレットの淡い面6色（`--yo-N-container` と `--on-yo-N-container`）。MyHood のユーザーアイコンと同じ割り当て |
| ロゴ・ファビコン | 画像として扱う（ミントと青の独自色のまま） |

### 使う時の注意

- **塗りの上に白（`#fff`）を直接書かない。** ダークでは primary も error も淡い色になるので読めない。`on-primary` / `on-error` を使う
- **淡い塗り（container）の上に on-surface-variant を置かない。** container の上は on-○○-container
- 文字は2段階（on-surface と on-surface-variant）だけ。opacity で薄めない
- 色を透かして使うのは決まった割合だけ: 淡い塗りボタン 14%、案内の面 primary 8%、エラーの面 error 10%、表の今日の行 primary 8%
- 値を変えたら `npm run check:contrast` を通し、同じ PR でこの表も直す。MyHood 側が変わったら値を写す

## 5. 文字

名前は MyHood（Tailwind）のクラス名と1対1。MyHood は 1rem = 17px なので、その実寸を px にした。

| 変数 | 大きさ | 使い道 | MyHood |
|------|--------|--------|--------|
| `--text-2xl` | 26px | 画面の大見出し | `text-2xl` |
| `--text-xl` | 21px | 見出し（大） | `text-xl` |
| `--text-lg` | 19px | 見出し（小）・カードの見出し | `text-lg` |
| `--text-base` | 18px | 本文・ボタン | `text-base` |
| `--text-sm` | 17px | ラベル・補足・メタ情報 | `text-sm` |
| `--text-xs` | 14px | バッジ・時刻など、単独で意味が完結しないものだけ | `text-xs` |
| `--text-2xs` | 12px | タブバーの文字などごく小さいラベルだけ | `text-2xs` |
| `--text-input` | 16px | 入力欄（16px 未満だと iOS がフォーカス時に拡大する） | `Input` の 16px |
| `--text-display` | 64px | ホームの時計など、画面の主役の数字だけ | — |

- 太さ: 本文 400 / メニュー 500 / ボタン・バッジ・リストの題名 600 / 画面とセクションの見出し・主役の数字 700
- 行間: 和文の本文 1.625（`--leading-relaxed`）/ 見出し 1.25（`--leading-tight`）
- 読む文章は 16px 以上、補足は 14px 以上。12px 未満は使わない。任意の大きさを作らず上の表から選ぶ
- 時刻・金額など桁をそろえたい数字は `font-variant-numeric: tabular-nums`

## 6. 余白・形・影

| 変数 | 値 | 使い道 | MyHood |
|------|----|--------|--------|
| `--space-1` | 4px | アイコンと文字の間 | `p-1` |
| `--space-2` | 8px | 部品の間（小）・ラベルと入力欄の間 | `p-2` |
| `--space-3` | 13px | 入力欄・エラー表示の内側 | `p-3` |
| `--space-4` | 17px | カード同士の間・画面の左右 | `p-4` |
| `--space-5` | 21px | カードの内側 | `p-5` |
| `--space-6` | 26px | 画面の上の余白（ログインなど） | `px-6` |
| `--space-7` | 34px | セクションの間（枠ではなく余白で区切る） | — |
| `--radius-xl` | 13px | 入力欄 | `rounded-xl` |
| `--radius-2xl` | 17px | 知らせ・エラー表示・要約の枠 | `rounded-2xl` |
| `--radius-3xl` | 26px | セル（カード・リスト）・タイルボタン | — |
| `--radius-full` | 9999px | ボタン（カプセル）・バッジ・アイコンボタン・セグメント・タブバー | `rounded-full` |
| `--tap-min` | 48px | 押せる要素の最小 | （MyHood は 44px） |

影は使わない（浮いているタブバーと、セグメント・タブの選択中の白い丸だけ）。

## 7. 画面の組み立て方

1. **セクションは枠だけで分けない。** 大きく太い見出し（アイコン付き）をセルの外に置き、セクションの間は `--space-7` 空ける。地とセルの明るさの差・色付きのアイコン・余白で区切る
2. **分かりやすい所にはアイコンを付ける。** 見出し・操作ボタン・リストの行の頭・要約のラベル・状態の札。意味は必ず文言でも伝える
3. **ボタンは押しやすさ優先。** 主な操作は大きなタイル（`Button tile`）を横に並べる。遷移先が増えても、目的の画面へ1タップで行ける方を選ぶ
4. 画面のてっぺんに主役の情報を中央ぞろえで置く（`.ui-hero`。ホームの時計、プロフィールのアバターと名前）
5. アカウント情報のように誤って変えると困るものは、最初は値だけを並べ、行をタップした時だけ入力欄を開く
6. **同じ画面への入口は PC・スマホそれぞれ1つだけ。** 同じ所へ行くボタンを複数置かない（PC はサイドバーの項目、スマホは下のタブ。設定はスマホだけプロフィール右上の⚙︎から。サイドバー左下のアカウントもプロフィールへの入口（Apple の App Store と同じ）。それ以外は入口を重ねない）
7. プロフィールは「自分の情報」（名前・パスワード。管理者はメンバーと会社も）、設定は「表示」と「ログアウト」（Canaria と同じ）。同じものを両方に出さない

## 8. 共通部品（`ui.tsx`）

画面はこの部品だけで組む。足りない部品は `ui.tsx` に足し、`/catalog` に載せてから使う。

| 部品 | 決まり |
|------|--------|
| `Button` | `primary`（青の塗り）は主な操作で1画面に1つ。`outline`（淡い青の塗り）は二番手、`ghost`（青い文字だけ）は補助。取り消せない操作は `danger`。形はカプセル。`icon` でアイコン、`tile` でアイコンの下に文字の大きなボタン（`.ui-tiles` に並べる） |
| `IconButton` | アイコンだけのボタン。ガラスの丸（表や行の中は `plain`）。`label`（読み上げ名）は必須。件数は `badge`。PC ではサイドバーから行ける画面への入口は `className="ui-mobile-only"` で隠す |
| `Header` | 画面の題名（h1・大きな太字。ホームは会社名）。上に貼り付く。`onBack` で左にガラスの丸い戻るボタン、右に `actions`。PC でサイドバーから直接行ける画面は `className="back-mobile-only"` で戻るを隠す |
| `TabBar` | スマホのメインナビ。画面下に浮くカプセル。項目は 3〜5 個。選択中は主色と白い丸で示し、太さは変えない |
| `Sidebar` | PC（幅 1024px 以上）のメインナビ。上にアプリ名（DayDeed。会社名はホームの題名に出すので重ねない）、中に線のアイコン付きの項目（選択中は青い文字＋淡いグレーの面）、一番下に使っている人（`onUser` で押すとプロフィール）。`.ui-shell` の中に置き、中身は `.ui-shell-main` に入れる |
| `Card` | セクション。`title`（h2）と `icon` はセルの外、中身は明るい角丸のセル。`className="plain"` でセルなし |
| `List` / `ListRow` | グループ化されたリスト。行の頭に `LeadingIcon` か `Avatar`、`subtitle` は題名の下、`trailing` は右。`onClick` で押せる行（›）、`expanded` で開閉の行、`tone` で「追加」「ログアウト」のような文字だけの操作行 |
| `LeadingIcon` | リストの行の頭の丸いアイコン。塗り（既定）/ `soft`（淡い）/ `muted`（グレー、未入力など） |
| `Stats` | 「小さいラベルの下に大きな値」の要約（箱なし）。`current` で今日などを青で強調、`columns` で列を固定（週の7日） |
| `SegmentedControl` | 少数の選択肢から1つ。カプセルの溝に白い丸。`fullWidth`、選択肢ごとに `icon` |
| `TextField` / `TextArea` / `SelectField` | ラベル必須（プレースホルダーをラベル代わりにしない）。補足は `hint`、エラーは `error`（入力欄と読み上げでつながる）。必須は `required`（＊が付く）。見た目は枠なしのグレーの塗り |
| `DateChip` | 日付の札（日にちの下に曜日）。タイムカードの行の頭に置く。今日は青の塗り |
| `ErrorMessage` / `Notice` | エラー / 案内・成功の知らせ。アイコン付きで、出た瞬間に読み上げる |
| `Badge` | 状態の札。`neutral` / `primary` / `error`。色だけで伝えないよう、アイコンか文言を必ず添える |
| `Avatar` | メンバーの頭文字。色は id から洋パレットの6色を選ぶので、どの画面でも同じ人は同じ色 |
| `Divider` | 区切り線（「または」など） |
| `Icon` | 飾りのアイコン。意味は隣の文言か `aria-label` で伝える |

## 9. アクセシビリティ（WCAG 2.1 AA）

- コントラスト: 文字 4.5:1 以上。**ライト・ダークの両方で**満たす（`npm run check:contrast`）
- 入力欄は Apple に合わせて枠なしのグレーの塗り。境目の見分けはラベル・塗り・フォーカス時の主色 2px の枠で補う（部品の枠 3:1 の扱いは要確認）
- 色だけで情報を伝えない（エラー・状態にはアイコンか文言を添える）
- 押せる要素は 48px 以上、隣り合う要素の間は 8px 以上
- フォーカスは `:focus-visible` に主色 2px の枠。`outline` を消すなら代わりの表示を必ず付ける
- 「視差効果を減らす」設定では動きを止め、「透明度を下げる」設定ではすりガラスを不透明にする
- 入力欄にはラベルを付け、補足・エラーは `aria-describedby`、エラー時は `aria-invalid`
- 拡大を禁止しない（viewport に `user-scalable=no` を書かない）
- 押せるものは `<button>` か `<a>`。見出しは h1 → h2 の順

## 10. ライト/ダークの仕組み

- `tokens.css` の色は `light-dark(ライト, ダーク)` の形で、1行に両方を持つ。どちらが効くかは要素の `color-scheme` で決まる
- `ui.css` の `:root` が `color-scheme: light dark` を宣言しているので、端末の設定に従う
- 設定画面の「表示」で自動/ライト/ダークを選ぶと、`<html data-theme="light|dark">` で固定する（`theme.ts`）。選んだ値はその端末の localStorage に保存し、起動時に描画前に戻す
- 対応ブラウザ: Safari 17.5 / Chrome 123 / Firefox 120 以降（`light-dark()` の対応範囲）

## 11. 禁止事項

- `tokens.css` 以外での hex・rgb の直書き
- 独自のボタン・入力欄・エラー表示（`ui.tsx` の部品を使う）
- 代わりの表示がないままのフォーカス枠の無効化
- 12px 未満の文字、表にない大きさの指定
- アイコンだけのボタンで `aria-label` がないもの
- グラデーション・カードの枠線と影（セクションは見出し・アイコン・余白・地とセルの差で分ける）
